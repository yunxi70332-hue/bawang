### 1.2 符合项（规范落实良好的方面）

1. **权限命名规约严格执行**：全部权限码符合 `<资源>:<动作>`（permissions.py 文档化 15 个权限点），`require_perm` 100% 覆盖业务端点；`/api/health`、`/api/auth/login`、`/pay/*`、`/internal/broadcast` 为**有意**的公开端点（token/内网密钥即凭证），全部有注释说明。
2. **SSE topic 与 REST 同口径**：`events.py _TOPIC_PERMS` 显式映射 topic→权限点（dashboard←account:read、pickup_scan←feature:pickup、intake←feature:order、proxy←settings:manage），与同域 REST 端点一致，杜绝"订阅侧权限旁路"。
3. **状态码语义全库统一**：202=异步受理（intake）、200+`duplicate:true`=幂等命中、409=状态机冲突（取消/重放/运行中）、422=结构化校验（预检带 `candidates` 候选清单）、429=限流（短信 65s/外部接收 120/min）、501=能力未接入（autopay）、503=页面缺失。无随意使用 500 表达业务语义的情况。
4. **动作端点统一 REST+RPC 混合风格**：资源 CRUD 用标准方法，状态动作统一 `POST /{resource}/{id}/{action}`（cancel/requeue/toggle-enabled/ack/trigger/disable/switch-full-price），无一例用 PUT/PATCH 做动作。
5. **列表端点三件套统一**：`page`(≥1) + `page_size`(1..100，默认20) + `keyword` 模糊（like 拼接），返回 `{total, items, ...}` 结构，14 个列表端点全部一致。
6. **双 router 模式规范**：orders.py、decision.py、intake.py 的"域内子资源 router + global_router"拆分均有模块头注释说明职责与挂载理由（app.py include 处也有行内注释）。
7. **模块 docstring 覆盖率 100%**：14/14 路由模块均有中文模块级注释，说明职责、鉴权方式、与其他模块的关系；关键端点有行为级 docstring（含幂等/失败语义）。
8. **后台线程横切规范统一**：daemon + `heartbeat()` 心跳 + 单轮异常永不退出 + `CHAGEE_*` 环境变量开关（≤0/0 即禁用）；conftest.py 统一在离线测试禁用全部线程。10 个常驻线程全部符合。
9. **双日志轨约定清晰**：用户写操作 `log_audit`（审计库）、系统/线程动作 `log_op`（oplog 独立库，trace_id 链路）；敏感字段脱敏 redact。
10. **路由注册顺序敏感点有防护**：`/static` 挂载与 SPA catch-all 的先后依赖在 app.py 有显式注释；SPA 兜底显式排除 `api/`、`docs`、`openapi` 前缀防误吞。

## 2. 前端路由与 API 层审计

### 2.1 符合项

1. **路由表结构统一**：16 条路由全部懒加载（`() => import(...)`）、`meta.title` 100% 填写（侧栏/面包屑双用）、需权限的页面 `meta.perm` 100% 填写、login 显式 `meta.public`；未匹配路径统一重定向 /dashboard。
2. **守卫职责单一清晰**：`beforeEach` 只做三件事——public 放行、未登录跳 login（带 redirect 回跳参数）、无权限回 dashboard；不做副作用。
3. **路径分组语义清晰**：`/ops/*`（协议业务）、`/decision/*`（决策配置）、`/system/*`（系统管理）、`/profile`（自助），与侧栏菜单三级结构一一对应，菜单按 `auth.can` 动态显隐与路由守卫双重控制。
4. **API 层单文件分域**：`api/index.js` 按 apiAuth/apiUsers/apiRoles/apiAccounts/apiOps/apiDecision/apiAudit/apiDashboard/apiIntake/apiKeepalive/apiSettings 分组，与后端路由模块一一对应；路径字符串与后端路由零漂移（抽查全部前缀吻合）。
5. **拦截器四职责齐备**：自动附 Bearer；响应体 server_time 时钟校准（消除倒计时漂移）；401 统一登出跳转；错误 detail 三形态（string/数组/对象）统一格式化弹窗；轮询类请求 `silent` 显式opt-out。
6. **状态管理最小化**：唯一 Pinia store（auth），权限判断 `can()` 供守卫/菜单/v-perm 三方共用，无冗余 store。

## 3. 横切规范抽查

- **测试隔离约定**：conftest.py 统一禁线程（CHAGEE_ORDER_WORKERS=0 等）、CHAGEE_OPLOG_DB 重定向、CHAGEE_PROXY_CONFIG/CHAGEE_MINT_ENABLED 测试覆写——17 套离线测试全部遵守，无互相污染。
- **测试运行约束（T1，已知约定）**：**离线套件须单独运行**（`pytest test_xxx_offline.py` 逐个跑）。同一 pytest 进程连跑多套件时，先跑套件的 DB 路径重定向环境变量会泄漏到后续套件（实测连跑 intake+queue 报 `no such table: system_users`；各自单跑 8/8、10/10、18/18 全绿）。属测试夹具设计债，不影响生产；建议后续各套件夹具用 fixture 显式管理 DB 路径而非进程级 env。
- **配置文件**：data/*.json 运行时配置（intake/decision/keepalive/proxy/pay_callback/alert/autopay）全部 fail-soft 载入（缺文件回退默认），路径统一 `_ACCOUNT_ROOT/data/`。
- **金额口径**：API 层金额一律字符串传输、Decimal 计算（services/decision evaluate_cost），无 float 直算。
- **时区**：全库本地时间 datetime.now() + 契约明确的"自然日口径"（剩 N 天计算），一致。
