# 功能模块逻辑说明（系统功能规格 v1.0）

> 更新：2026-09-30 · 适用版本：v1.0 · 对象：霸王茶姬多账号管理系统（`account_system/`，FastAPI 后端 :8000 + H5 收银台进程 :8010 + Vue3 前端）
> 阅读指引：§1 系统总览 → §2 各功能模块（每个模块含职责/关键逻辑/接口/依赖开关）→ §3 后台线程总表 → §4 权限模型。
> 接口报文级细节见 [intake_api_reference.md](intake_api_reference.md)（订单中枢）与 [decision_api_contract.md](decision_api_contract.md)（决策域契约 §1-16）。

## 1. 系统总览

```
                    ┌────────────── 主 API 进程 (uvicorn app:app, 127.0.0.1:8000) ──────────────┐
 Vue3 SPA (web/dist 托管) ──JWT──▶ 14 路由模块 ──▶ services 层 ──chagee_bridge──▶ scripts/chagee_*.py 纯协议层 ──▶ 茶姬服务端
 外部客户平台 ──X-Api-Key──▶ /api/intake/v1/*（异步订单中枢）                    │
 手机浏览器 ──pay_token──▶ ┌── 收银台进程 (pay_portal:app, 0.0.0.0:8010) ────────┤ 同库(SQLite WAL) 双进程
                          └── 主 API 也挂 /pay/*（本机访问）                     │
                                            10 个常驻后台线程（校准/收口/推送/备份/监控…）┘
```

三大角色进程：**主 API**（管理面全部功能+worker 池）、**收银台进程**（仅 /pay/* 公开路由，局域网暴露）、**云手机隧道子进程**（WebView 代理）。双进程共享同一 SQLite 库（WAL），跨进程通知走 `/internal/broadcast`。

## 2. 功能模块说明

### 2.1 认证与用户体系（auth / users / roles / security / permissions）

**职责**：系统用户登录（JWT HS256，12h 有效，密钥持久化 data/secret.key）、用户 CRUD 与密码重置（bcrypt）、角色权限矩阵（RBAC）。

**关键逻辑**：
- 权限点 15 个，命名规约 `<资源>:<动作>`，与后端 `require_perm`、前端路由 `meta.perm`、按钮指令 `v-perm` 三端一一对应（permissions.py 是唯一权威目录）。
- 内置角色 admin（全量，不可改删）/ operator（11 项）/ viewer（2 项），每次启动 seed 重置对齐目录。
- 防呆规则：不能删自己/自停用；admin 角色权限锁定全量；有用户的角色不可删；admin 用户不可删。
- 登录/登出/失败全写审计日志。

**接口**：`/api/auth/login|me|change-password`；`/api/users` CRUD+reset-password（user:manage）；`/api/roles` CRUD（role:manage）。

### 2.2 茶姬账号管理（accounts + chagee_bridge）

**职责**：茶姬账号全生命周期：创建（生成设备身份 uuid + data/accounts/<id>/ 隔离目录）→ 短信验证码协议登录 → 在线维护（whoami 自检）→ 登出/删除。

**关键逻辑**：
- **DB 为凭证唯一事实源**：token/uuid 落库，本地仅存 session.json/device.json 快照；`build_client(account)` 按账号构造隔离协议客户端。
- **协议登录流**：send-sms（服务端 65s 限流→429；真实投递）→ login（验证码换 token → whoami 回填昵称 → **登录即同步券档案入库**，CHAGEE_LOGIN_COUPON_SYNC=0 可关）。
- **凭证失效治理**：任何链路撞 SessionExpired → 账号置 expired（check 端点/watcher/保活跃/校准线程四处统一）。
- 换绑手机号强制 online→pending 清 token；online 账号不可直接删。

**接口**（前缀 /api/accounts）：CRUD（分级权限）+ `/{id}/token`（完整 token 复制入审计）+ send-sms/login/logout/check（account:login）。

### 2.3 游客菜单与本地规格库（ops + menu_spec）

**职责**：F3 游客模式城市/门店/菜单/SKU 查询 + **本地菜单规格库**（文案规格→数字 ID 的兜底命中链）。

**关键逻辑**：
- 三表缓存：menu_spec_options（全局规格主数据）、menu_spec_values、menu_goods_cache（门店×SPU 快照）；每日刷新线程全量刷新活跃门店（有订单 ∪ 已缓存）。
- **resolve 命中链**：`resolve_by_sku`（L1 本地 → L2 回源重查）；`resolve_spec_texts` 三级匹配——归一化精确（含别名表 SPEC_ALIASES）→ 包含式模糊 → **歧义/未命中抛 SpecResolveError 带候选清单（宁拒不猜）**。
- get_goods_cached 本地优先 + TTL（86400s）回源 write-through。

**接口**：/api/ops/cities、/stores（5 分钟全页缓存）、/menu、/goods、/menu/spec/refresh|status|resolve（feature:menu）。

### 2.4 优惠券域（ops 券查询 + orders 券档案/使用记录 + 券生命周期）

**职责**：F4 登录态券三列表查询与入库、全库券档案搜索、券使用日志五态状态机。

**关键逻辑**：
- **券桶约定**：effective（可用）/ historical（已用/过期）双桶；同步时「历史先写、可用后写胜出」，防旧快照倒灌。
- **五态使用日志**：pending（下单预记）→ success（支付收口原地迁移）/ rolled_back（取消回滚，单行生命周期）/ failed（下单失败）/ cancelled；state_history 留轨迹。
- **四个自动迁移触发点**（2026-09-30 收口）：下单 create、支付收口 paid、取消/超时回滚、券核销确认——券自动进历史桶，无需人工。
- 判型：券文案 parse_benefit/classify_coupon → 面额/折扣率/兑换券；**折扣率券（7折）按×折扣计扣减，非减 7 元**（服务端 discountList 回填为唯一权威）。

**接口**：POST /api/ops/accounts/{id}/coupons（单账号拉券落库）、/coupons/sync-all（全账号，feature:coupon）；GET /api/ops/coupons/search、/coupon-usage-logs、/accounts/{id}/coupons/records。

### 2.5 下单工作台 F5（orders：settle/create + 支付链）

**职责**：手动下单全链——购物车试算（draft）→ 选券下单（零元单/差额单双分支）→ 支付（H5 收银台/支付参数串）→ 取消/续付/原价切换。

**关键逻辑**：
- **settle_core**：试算生成 draft（模块级缓存 10 分钟 TTL），服务端回填 discountList 为扣减唯一权威。
- **create_core**：下单三道资金风控——settle.buyer_real_price / pay link.total_amount / 方案 max_pay_amount 全部服务端校验（fail-closed）；券自动切换（首选券不可用按策略取次优）；决策挂钩 decision_log_id 回填。
- **支付形态**：零元单直接 completed+取餐码；差额单铸 **pay_token 会话**（一单一链接、续付 token 不变）→ H5 收银台（8010）/官方收银台直链（cashier_mint 铸造）/支付参数串（pay_params JSON v1）。**自动代付不做**（支付宝已三度拒绝，红线=密码永远人工输入），提供 /pay/pending 轮询+pay_assistant 人工助手。
- 取消：本地置取消 + 券回滚（order_reconcile.rollback_coupon_usage）+ 会话 cancelled。

**接口**（/api/ops/accounts/{id}/orders）：POST settle/create/{no}/pay|continue-pay|cancel|switch-full-price|cashier-url；GET {no}/cashier|pay-params；全局 GET /pay/pending、POST /orders/reconcile。

### 2.6 取餐查询 F6（orders 查询族）

**职责**：订单列表/详情/状态/等待信息 + 取餐码多通道获取 + 全量扫描。

**关键逻辑**：
- **取餐码四通道**：零元单即时 / pay-watcher 2s 收口 / H5 探针 / 全量扫描兜底（POST /pickup/scan-all 后台线程 + SSE 进度推流 pickup_scan topic）。
- 取餐多维模糊搜索（/pickup/search，单号/取餐码/手机号/门店）。

**接口**：GET 订单列表/详情/status/waiting（feature:pickup）、POST /pickup/scan-all、GET /pickup/scan-status、/pickup/search。

### 2.7 下单决策系统（decision 路由 + services/decision）

**职责**：自动化下单的"大脑"——客户支付价+券+套餐+成本规则折算利润，pass/blocked 判定与选号选券。契约 §1-16 见 decision_api_contract.md。

**关键逻辑**：
- **decide 引擎四级漏斗**：菜单 resolve → 套餐命中（价格区间+时段跨零点+商品圈定）→ 券候选初筛+rank_candidates 三策略排序（cost_first/zero_pay/expiry_first）+ 优先级层重排 → **三阈值判定**（min_profit/min_margin/max_order_cost，全 Decimal）。
- **下单方案（order_plans）**：策略+优先级层+**支付金额上限 max_pay_amount（fail-closed：空/非法默认拒绝）**；停用方案语义：decide 显式引用 422、create 自动回落系统排序。
- 券类型绑定（§15）、剩 N 天自然日口径（§16）、库存扫描（/scan 全账号拉券盘点）、盈利报表（仅成单行计金额）、决策流水留痕 DecisionLog。
- **decide_core 同时是订单中枢 worker 的执行链第一环**（同一实现零漂移）。

**接口**（/api/ops/decision/*）：packets/cost-rules/cost-categories/order-plans CRUD+toggle、config、scan、coupon-inventory、coupon-types、sku-search（兼旧路径 plan-drinks/search）、profit-report、logs；POST /api/ops/orders/decide（feature:order）。

### 2.8 异步订单中枢（intake + intake_registry/order_queue/order_worker/intake_notify）

**职责**：高并发订单接收与全自动执行——内外双接收接口、SQLite 持久化队列、worker 池全自动下单、按单回调。完整 API 见 [intake_api_reference.md](intake_api_reference.md)。

**关键逻辑**：
- **接收快、执行稳**：接收路径只做校验+预检+毫秒级短事务（**登记+入队同一事务原子提交**——选 SQLite 队列的核心收益）即返 202；重活全在 worker。
- **可靠性语义（at-least-once+消费幂等）**：单条 UPDATE…RETURNING 原子认领（attempts 认领时+1）；失败 30/120/300s 阶梯退避；致命错误（决策 blocked/OrderHang 结果不确定）直达死信不耗退避；崩溃恢复 reclaim_orphans（600s 可见性超时）；认领后终态/已成单直接 ack（绝不重复下单）。
- **状态机**：registered→enqueued→processing(decide→settle→create)→completed / awaiting_payment→completed / failed / cancelled；CAS 迁移非法拒绝留痕，completed 不可逆。
- **失败分类**：HTTPException 语义与 F5 路由完全一致——可重试（409 账号占用/凭证失效、502 协议、400 券耗尽）重跑 decide 换号换券；致命（"结果不确定"/"一致性校验失败"）进死信等人工。
- **外部适配（KFC 系）**：linkId=skuId；storeNo 缺省回落 intake_config.default_store_no；密钥 sha256 落库明文仅一次；每密钥 120/min 滑窗限流；**单号归属密钥隔离**。
- **回调**：order_created/completed/pickup/cancelled 四事件，X-CHAGEE-Signature=HMAC-SHA256(raw_body)，1/2/4s 退避 4 次独立线程投递。

**接口**：/api/intake/orders*（feature:order）、/api/intake/queue/*、/api/intake/keys*（intake:manage）、/api/intake/v1/*（X-Api-Key）。

### 2.9 H5 收银台（payportal + pay_session + pay_broadcast）

**职责**：差额单的移动端支付页——pay_token（token_urlsafe(32)）即公开 URL 凭证，任意手机浏览器可开，无 JWT。

**关键逻辑**：
- **会话模型**：一单一链接，续付/重铸 token 永不变；状态迁移 CAS（mark_session 单条 UPDATE WHERE status!=目标态，防 watcher/H5 探针双收口）。
- **双进程架构**：主 API 8000 本机可访问 /pay/*；局域网由独立进程 pay_portal:app 绑 0.0.0.0:8010 暴露**同一组路由**（管理 API 不进局域网）；跨进程秒级通知 POST /internal/broadcast（X-Internal-Token 常数时间比对），迟到旧通知不会倒拨终态。
- **页面能力**：实时状态 SSE（/pay/{token}/events，终态即闭流）、倒计时（server_time/deadline_ts 下发+三端偏移校准）、续付重铸（remint）、券差额单→原价单切换（switch-full-price：取消旧单+券回滚+按快照原价重下+新会话）。
- 收银台链接铸造：cashier_mint 三 provider（protocol 纯 HTTP 复刻 mspay 加密 RPC，默认 / frida 云手机 / auto 降级），CHAGEE_MINT_PROVIDER 切换。

**接口**：GET /pay/{token}（页面）、/{token}/info|status|events、POST /pay/{token}/remint|switch-full-price；POST /internal/broadcast。

### 2.10 支付收口与订单校准（payment_events + order_reconcile）

**职责**：两条后台保障线——pay-watcher 2s 扫支付会话自动收口；order-reconcile 60s 扫超时待支付单与茶姬侧对账。

**关键逻辑**：
- **pay-watcher**：无人开着 H5 也能收口。已支付：先 CAS 置 paid 赢家才做取餐码 detail/审计/回调（只执行一次）；已取消：券回滚+会话 cancelled；过宽限线连续 3 轮待支付→会话 expired。**挂钩订单中枢**：收口时惰性调 intake_notify.on_chagee_order_paid/cancelled 推进登记单。
- **order-reconcile**：status=1 过宽限线（120s）的单，以茶姬 getOrderStatus 为准——已取消(7)→本地取消+回滚券；已支付(3/6)→回填+券确认核销（confirm_coupon_usage：historical 桶+日志 pending→success 原地迁移，幂等）；仍待支付不动。
- 外部支付回调（客户系统）：paid/pickup 事件 HMAC 签名投递（pay_callback_config.json）。

**接口**：GET /api/ops/pay-events；POST /api/ops/orders/reconcile（手动全库校准）。

### 2.11 账号保活跃（keepalive 路由 + services/keepalive）

**职责**：每天定时（默认 10:30）用在线账号 token 间歇访问广东省（cityCode 44*，21 市 781 店）菜单接口，维持账号活跃度。

**关键逻辑**：
- **真鉴权**：菜单链本身无 token，故每账号每轮先 whoami 验活——失效即置 expired + ERROR 告警（不静默）。
- **拟人节奏**：账号 round-robin 轮转分配门店；请求间 5-12s 随机停顿；瞬时失败 3s/6s 退避重试 2 次；token 失效不重试。
- 配置 data/keepalive_config.json（30s 热更新）；运行落 keepalive_runs/keepalive_records 两表；失败率/枚举空两类阈值告警（log_monitor.create_alert 公共入口）。

**接口**（/api/ops/keepalive）：GET status/config/runs/runs/{id}（account:read）；PUT config、POST trigger（account:login，运行中 409）。

### 2.12 网络出口管理（settings 路由 + net_proxy）

**职责**：茶姬域请求（chagee.com/bwcj.com）统一经大陆 IP 代理出口——monkeypatch urllib urlopen 全局接管，异常自动回退直连（fail-open 可用性优先）。

**关键逻辑**：
- 两种模式：api 提取式代理池（服务商 API 拉候选 ≤3 实测择优，海量 IP 文本解析） / manual 固定代理；http/socks5。
- **健康判定以真实茶姬网关可达为准**；直连基线每 300s 探一次；连续 2 次代理失败自动降级直连并告警；状态经 SSE topic=proxy 实时推送，切换/回退全落 oplog（proxy.*）。
- 干跑诊断 /proxy/test：提取→CONNECT 隧道→经代理访问茶姬→直连基线全链路实测，不改不落状态。

**接口**（/api/ops/settings，settings:manage）：GET/PUT /proxy、POST /proxy/test|refresh、GET /proxy/logs。

### 2.13 操作日志与告警（oplog + log_monitor + logs 路由）

**职责**：全局结构化操作日志（独立库 data/logs/oplog.db，双进程共享）+ 六规则告警。

**关键逻辑**：
- **oplog**：log_op 敏感键脱敏、写失败降级不伤主流程；trace_id（contextvars）贯穿 HTTP 请求与 worker 消费链；heartbeat 线程心跳限频落库（60s）。
- **六告警规则**：error_burst（5min ERROR≥3）/ thread_dead（预期线程消失）/ heartbeat_stale（心跳超时=循环停滞）/ oplog_failure（日志写失败）/ queue_dead_backlog（死信>0）/ queue_backlog_high（最老 pending>5min）；落 op_alert 表 + webhook/SMTP 外发（alert_config.json 未配置仅落库）。

**接口**（/api/ops）：GET /logs、/logs/trace/{id}、/alerts（audit:read）；POST /alerts/{id}/ack、/logs/scan（user:manage）。

### 2.14 备份与运维保障（backup + cloud_tunnel + dashboard）

- **backup**：每日 sqlite3 backup API 一致性快照 app.db + oplog.db → data/backups/，保留 14 天（可配）自动清理。
- **cloud_tunnel**：云手机 WebView 代理隧道子进程托管（DETACHED_PROCESS 分离，60s 检活、死亡 5s 重启，CHAGEE_TUNNEL_ENABLED=0 停）。
- **dashboard**：collect_dashboard_stats 四域聚合（账号/券/订单+盈利/审计）唯一数据源；REST 首拉 + SSE 推送（5s 指纹变化才推）双通道。

### 2.15 前端应用（web/）

- **路由**：16 条懒加载路由，meta.title/perm/public 三约定；守卫=未登录跳 login（带 redirect）+无权限回 dashboard。路径分组 /ops（业务）/decision（决策）/system（管理）。
- **API 层**：单文件 api/index.js 按 11 个域分组与后端模块一一对应；拦截器统一 Bearer/401 跳转/server_time 时钟校准/错误弹窗（silent 可opt-out）。
- **权限**：路由级 meta.perm + 按钮级 v-perm 双重控制（2026-09-30 审计后 KeepaliveView/IntakeOrdersView 管理按钮已补齐）。
- **实时**：utils/sse.js 订阅 /api/events（dashboard/pickup_scan/intake/proxy 四 topic）；utils/clock 三端偏移校准消除倒计时漂移。

## 3. 后台线程总表（全部 daemon + heartbeat + CHAGEE_* 开关）

| 线程 | 间隔 | 职责 | 开关（≤0/0 停） |
|---|---|---|---|
| order-worker-N（默认2） | 1s 轮询 | 订单中枢消费执行链 | CHAGEE_ORDER_WORKERS |
| pay-watcher | 2s | 支付会话收口 | CHAGEE_PAYWATCH_INTERVAL_SECONDS |
| order-reconcile | 60s | 超时单对账校准 | CHAGEE_RECONCILE_INTERVAL_SECONDS |
| dashboard-push | 5s | 仪表盘指纹推送 | CHAGEE_DASHBOARD_PUSH_INTERVAL_SECONDS |
| proxy-monitor | 30s 可配 | 代理出口健康检测 | CHAGEE_PROXY_CHECK_INTERVAL_SECONDS |

## 4. 权限模型（15 权限点）

| 分组 | 权限码 | 控制面 |
|---|---|---|
| 账号管理 | account:read / create / update / delete / login | 账号 CRUD 分级；update 兼控完整手机号可见 |
| 协议功能 | feature:menu / coupon / order / pickup | F3/F4/F5/F6 + 订单中枢登记（order） |
| 系统管理 | user:manage / role:manage / audit:read / settings:manage | 用户/角色/审计与日志读/代理设置 |
| 下单决策 | decision:manage | 套餐/成本/方案/配置/扫描/报表（decide 本身=feature:order） |
| 异步订单 | intake:manage | 中枢管理：取消/重放/死信/密钥 |

内置角色：admin（15 全量）/ operator（11 项，无删除/用户/角色/设置）/ viewer（account:read + feature:menu）。
