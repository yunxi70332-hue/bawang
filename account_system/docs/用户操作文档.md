## 1. 系统简介

本系统是「霸王茶姬六功能纯协议项目」的多账号管理平台，把协议脚本能力包装为带权限控制的 Web 服务：

| 能力 | 说明 | 对应协议功能 |
|---|---|---|
| 多账号管理 | 茶姬账号的创建/查询/编辑/删除，每账号独立设备身份与隔离会话 | 功能1 设备注册 |
| 协议登录 | 生产短信验证码登录（两步确认），whoami 会话自检，协议登出 | 功能1 登录 |
| 游客菜单浏览器 | 城市 → 门店 → 菜品 SKU 级联查询（无需登录态） | 功能3 数据获取 |
| 优惠券查询 | 登录态可用/历史双列表分类 + 饮品兑换券识别 | 功能4 账号功能 |
| 取餐查询 | 占位页（协议层 Phase 5/6 未开发，如实标注） | 功能6 订单查询 |
| RBAC 权限 | 11 个细粒度权限点，接口与按钮双重校验 | — |
| 审计日志 | 登录/变更/协议外向动作全量留痕 | — |

**目录结构**

```
account_system/
├── server/            # Python FastAPI 后端
│   ├── app.py         # 入口（含 API 文档 /docs）

├── data/              # 运行时数据（app.db / 各账号隔离会话 / secret.key）
└── docs/              # 本文档
```

## 2. 启动与访问

### 2.1 一键启动（推荐）

双击 `start_server.bat`（或）：

```bash
cd account_system/server
python -m uvicorn app:app --host 127.0.0.1 --port 8000
```

浏览器访问 **http://127.0.0.1:8000** （前端构建产物由后端直接托管）。

### 2.2 开发模式（前后端分离调试）

```bash
# 终端1：后端
cd account_system/server && python -m uvicorn app:app --port 8000
# 终端2：前端 Vite 热更新（/api 自动代理到 8000）
cd account_system/web && pnpm dev     # http://localhost:5173
```

## 4. 角色与权限（RBAC）

### 4.1 内置角色

| 角色 | 定位 | 权限要点 |
|---|---|---|
| `admin` | 系统管理员 | 全部 11 项权限（内置锁定不可改） |
| `operator` | 运营人员 | 账号增改（**不可删除**）、协议登录、菜单/券查询、审计查看 |
| `viewer` | 只读观察者 | 仅查看账号（手机号脱敏）+ 游客菜单 |

### 4.2 权限点清单

| 分组 | 权限点 | 作用 |
|---|---|---|
| 账号管理 | `account:read/create/update/delete/login` | 查看/新建/编辑/删除/协议登录 |
| 协议功能 | `feature:menu/coupon/order/pickup` | 游客菜单/券查询/下单/取餐查询 |
| 系统管理 | `user:manage` `role:manage` `audit:read` | 用户/角色/审计 |

权限在**后端接口**（403 拦截）与**前端按钮**（无权限不渲染）两层同时生效；修改角色权限矩阵后，受影响用户需重新登录或刷新令牌内权限快照（重新登录最可靠）。

### 4.3 常见权限差异表现

- viewer 打开账号列表：只有「详情」按钮，手机号显示 `159****1290`；
- viewer 看不到侧边栏「系统管理」分组；
- operator 无「删除账号」「用户管理」「角色管理」入口。

## 5. 账号管理操作

### 5.1 新建账号

1. 「账号管理 → 茶姬账号」→ 右上角 **新建账号**；
2. 填写：备注名（必填）、手机号（11 位大陆号，必填）、分组、备注；
3. 底部两个按钮任选：
   - **保存**：仅创建账号，稍后手动点「登录」；
   - **保存并发送验证码**（推荐）：**创建 + 真实发送验证码一步完成**，同一弹窗内直接切换到「输入验证码」界面，输入验证码后点 **登录并保存会话** 即完成全部流程（警告信息已前置显示在表单下方）；
4. 若暂不登录：在输码界面点「完成，返回列表」或直接关闭，账号已保存为「待登录」，可随时从列表行 **登录** 继续（见 5.2）；
5. 创建时系统为该账号生成**独立设备身份 uuid**（协议层「设备注册」等价物），状态为「待登录」。

### 5.2 协议登录（短信验证码，功能1）

> ⚠️ 生产外向动作：会向该手机号**真实发送**验证码，且协议登录成功会使该账号在其他端（如 App）的登录态**立即失效**（单会话语义，无 refresh token 自动续期）。

1. 账号行点击 **登录** → 弹出两步对话框（新建流程内已合并为单弹窗，此处为已有账号入口）；
2. 第一步：核对手机号 → 点击 **确认发送验证码**（60 秒内仅可发一次，按钮自动倒计时）；
3. 第二步：输入收到的验证码 → **登录并保存会话**；
4. 成功后：状态变「在线」，自动回填茶姬昵称与 customerId；token/sk 存入数据库（永不下发前端，仅显示指纹如 `eyJhbGciOi...len=608`）。

### 5.3 状态说明与运维动作

| 状态 | 含义 | 处理 |
|---|---|---|
| 待登录 | 无有效会话 | 发起协议登录 |
| 在线 | token 有效 | 可执行券查询等登录态功能 |
| 凭证失效 | 被其他端登录踢下线 / token 过期 | 「检查」确认后重新登录 |
| 已停用 | 人工禁用 | 所有协议操作被拒绝，需编辑改回 |

- **检查**：调用 whoami 实时验证会话（需账号:login 权限）；
- **详情**：抽屉查看完整信息（有 `account:update` 权限者可见完整手机号）；
- **编辑**：改备注/分组/手机号/停用状态。**换绑手机号会使在线会话重置为待登录**；
- **删除**：在线账号需先登出/停用；删除会同时清除本地会话文件（需 `account:delete` 权限）；
- **协议登出**（详情抽屉内）：服务端注销 token，账号回到待登录。

### 5.4 安全设计

- 手机号列表脱敏，完整号仅 `account:update` 权限可见；
- token/sk 仅存后端数据库，接口只回指纹；
- 所有变更与协议外向动作（发短信/登录/登出）写入审计日志。

## 6. 协议功能

### 6.1 游客菜单浏览器（功能3）

无需茶姬登录态，四级联动：

1. 选择城市（生产 cityList，350+ 城，支持搜索）；
2. 选择门店（支持名称搜索，显示门店号/地址）；
3. 菜品表自动加载：**缩略图**（点击放大）/ 分类 / 商品 / 起售价 / 在售状态（在售靠前）；
4. 点击商品行 → 抽屉展示商品头图（可翻看详情长图）与 SKU 明细（规格 / 价格 / 库存 / SKU ID）。

页面顶部展示**自取路径参数族**（功能2）：`saleType=1（自取菜单）、saleChannel=2、businessType=1/2、orderType=0、deliveryType=1*（推断值）`。

### 6.2 优惠券查询（功能4）

1. 「协议功能 → 优惠券查询」选择一个**在线**账号；
2. 点击查询 → 汇总卡片（可用/历史/饮品兑换券/券种类）+ 分类汇总表 + 全部券明细；
3. 券明细包含：归属（可用/历史）、名称、**券码**（couponCode）、权益、状态、适用场景、**有效期**（生产返回毫秒时间戳，系统已格式化为 `YYYY-MM-DD HH:mm`）；
4. 说明：
   - 分类依据 effective-list（可用）/ historical-list（历史）列表归属 + bizType/权益关键词；
   - 「饮品兑换券」为 0 元下单（功能5）的联动券种，高亮识别；
   - `order-coupon-list` 生产环境 404 未部署（2026-09-23 实测），页面如实标注。

### 6.3 下单工作台（功能5）

四步流程（`协议功能 → 下单 · F5`，需 `feature:order` 权限 + **在线账号**）：

1. **选账号**：仅「在线」状态账号可选（无在线账号时页面引导去账号管理登录）；
2. **选门店与商品**：城市 → 门店 → 菜品（含图片/售罄标记）→ SKU 抽屉选规格与数量（1-99）；
3. **试算与选券**：点击「去结算」调用真实试算（cart_add + settlePrice，服务端生成 10 分钟有效草稿）；预览展示商品明细、总额与**卡片式选券界面**（每张券完整显示：名称/面额/门槛/有效期/券码/推荐标记/预计抵扣；不可用券自动置灰并标注原因——已过期/未生效/门槛未满足/服务端标记不可用）；服务端在下单前执行**五重验证**：① 券ID↔账号(token)归属映射（防跨账号盗用）② 可用性 ③ 有效期 ④ 使用门槛 ⑤ 试算在列，任一不通过即拒绝并留痕；
4. **确认下单**：确认弹窗展示完整订单预览（账号/门店/商品/规格/数量/券/应付金额）；**应付为 0 时显示红色警示「0 元单会真实制作饮品！不取自然作废」**；确认后才真正调用 createOrder。

**结果两分支**：
- **0 元成单**：直接进入制作中，展示订单号/状态/取餐码，可一键跳转取餐查询；
- **差额支付**（应付>0）：展示支付窗口 10 分钟倒计时与**双支付模式**：
  - **人工模式（默认）**：展示支付宝支付串（order_str）与指引——复制支付串在手机支付宝完成支付；「重新生成支付串」= 续付（continuePay 重铸，10 分钟窗口内）；
  - **自动模式（实验性）**：支付宝 H5 收银台驱动脚本。**实测结论：登录墙（滑块+短信）+ 支付密码 + 设备风控三道人工环节，纯脚本无法稳定通过**——未配置时返回配置指引（`data/autopay_config.json`），配置后也仅执行只读探测腿并如实报告需人工环节。扣款 POST 被脚本结构性禁止（安全不变量）。建议以人工模式为主。

**安全边界**：单次一单（存在待支付订单时拒绝再下单）；下单前草稿预览 + 显式确认双门；createOrder 无幂等键——结果不确定时系统引导「先查单再决定是否重试」（防悬挂）；金额三向一致性断言失败即中止。

### 6.5 优惠券使用规则与券使用记录

**券档案（数据库全量存储）**：每次 F4 券查询与 F5 试算都会把券全量信息同步入库（`coupon_records` 表）——券ID（全局唯一）↔ 归属账号（含 token 指纹）映射、完整名称、面额、门槛、有效期毫秒时间戳、可用性、最近使用订单等。安全语义：**每个券ID唯一归属一个账号**，下单时校验提交的券必须属于当前下单账号，跨账号使用将被拒绝并记入使用日志。

**券使用日志（`协议功能 → 券使用记录`）**：每次带券下单（无论成败）自动留痕——使用时间 / 订单号 / 券ID与名称 / 茶姬账号 / 系统操作人 / 抵扣金额 / 总额与实付 / 结果（使用成功 · 验证拒绝 · 下单失败）/ 拒绝或失败原因。页面支持关键字与结果筛选，顶部统计条展示成功/拒绝/失败计数与**累计抵扣金额**，供查询与统计分析。

**金额自动抵扣链路**：选券后服务端用购物车快照复跑选券试算（settlePrice 以 discountList 提交券 → 服务端计算抵扣后金额），createOrder 携带折扣行（discountId=券ID）完成自动抵扣，并做三向金额一致性断言；购物车加购时校验售罄/库存变更（失效列表非空即报差异）。

**券型感知（2026-09-28）**：券分两类——固定面额券（「20元」）与折扣率券（「7折」「7.8折」）。折扣率券的抵扣由茶姬服务端按 总价×(10−n)/10 计算并随试算回填，**下单折扣行以服务端回填值为唯一权威**（本地折率换算仅兜底）；券档案库「面额」列折扣率券原样显示「7折」（不再误显「7元」），下单工作台对折扣率券展示面额与预计抵扣。

### 6.4 取餐查询（功能6）

`协议功能 → 取餐查询 · F6`（需 `feature:pickup` 权限 + 在线账号）：

- **订单列表**：今日/历史切换，含订单号/取餐码（高亮）/状态/应付/门店/时间；待支付订单行有「支付」「续付」按钮，并自动每 5 秒状态探针（仅页面打开时，状态变更即提示并刷新）；
- **详情抽屉**：状态/取餐码大字展示/商品明细/券核销（promotionName/优惠金额/券码）；待支付订单显示支付窗口倒计时（≤2 分钟变红）与双支付模式入口；
- **等待信息卡**：制作中订单展示前方等待杯数/预计等待时间/队列上限（getWaitingInfo），默认 3 秒自动刷新（可暂停）；
- 订单状态枚举：1 待支付 / 3 制作中 / 6 已完成 / 7 已取消（**已取消为终态不可救单**，只能重新下单）；
- 本地订单记录（OrderRecord 表）随查询自动同步，含取餐码/门店/金额/券码快照。

## 7. 系统管理（仅 admin / 相应权限）

### 7.1 用户管理

新建用户（用户名 2-32 位字母数字下划线、初始密码 ≥8 位）、编辑角色/启用停用、重置密码、删除（admin 内置账号不可删，不能删自己/停用自己）。

### 7.2 角色权限

- 角色列表显示权限数/用户数；点击 **编辑权限** 打开权限矩阵（按分组勾选）；
- admin 内置角色权限全量锁定；operator/viewer 可调整权限但不可删除；
- 有用户挂载的自定义角色不可删除，先改用户角色。

### 7.3 审计日志

全量操作留痕：时间 / 用户 / 动作（如 `account.send_sms`）/ 对象 / 来源 IP / 详情 JSON。支持关键字与动作类型筛选。关键动作类型：

| 动作 | 含义 |
|---|---|
| `auth.login` / `auth.login_failed` | 系统登录成功/失败 |
| `account.create/update/delete` | 账号变更 |
| `account.send_sms/login/logout/check` | 协议外向动作与会话自检 |
| `feature.coupon` | 券查询 |
| `user.*` / `role.*` | 用户与角色管理 |

### 7.4 个人设置

查看个人信息与权限清单；修改密码（≥8 位、含字母与数字、需原密码）。

## 9. 常见问题（FAQ）

| 现象 | 原因与处理 |
|---|---|
| 短信发送提示 429 | 服务端 60s 限流（或本系统 65s 防护窗），等待倒计时结束 |
| 登录成功但不久后「凭证失效」 | 单会话语义：该账号在 App 等其他端重新登录会踢掉协议会话；重新登录即可 |
| 券查询返回 409 | 账号 token 失效（状态已自动置为凭证失效），重新协议登录 |
| 下单提示「草稿已过期」 | 试算草稿 10 分钟有效，回第③步重新试算 |
| 下单提示「存在待支付订单」 | 单次一单保护：先到取餐查询处理待支付单（支付/等自动取消） |
| 下单提示「结果不确定」 | createOrder 无幂等键的防悬挂保护：**先到取餐查询页查单**确认是否已成单，勿直接重试 |
| 下单提示「一致性校验失败：抵扣合计不符」 | 已修复（2026-09-28）：折扣率券（7折/7.8折等）曾被当固定面额券本地估价，与茶姬实扣不符被断言拦截。现下单行以服务端回填为准；若再出现请截图反馈（真·金额不符同样走此拦截，属保护行为） |
| 待支付订单超 10 分钟 | 自动取消（autoCancel 终态），只能重新下单 |
| 自动支付返回 needs_interaction | 实验性功能的诚实终态：登录墙/支付密码/设备风控需人工，见 `data/autopay_config.json` 配置说明；请用人工模式 |
| 下单提示「协议错误 [99997] …」 | 已修复（2026-09-26 生产迭代）：currentGoodId 自动生成、公共头升级 avc 2060/apv 1.0.3、购物车 get 补 storeChannelCode、settle 行改 wire 模板、加购带默认属性。若个别商品仍报错，多为**季节/限时商品**被服务端拒绝——换常规在售商品即可 |
| 下单提示「本次加购 SKU 已失效」 | 所选 SKU 售罄/下架/库存变更（引擎按目标 SKU 精确拦截），换品重试 |
| 试算可用券为 0 | settle 的可用券按下单语境计算（门店/商品），与券列表页不同；换商品或确认券状态 |
| 删除账号被拒 | 在线账号需先登出或停用 |
| viewer 看不到某菜单/按钮 | 权限不足所致，找 admin 调整角色权限矩阵 |
| 页面刷新 404 | 仅旧版本问题，v1.0 已修复（SPA 路由兜底）；确认访问 8000 端口且后端为最新代码 |
| 修改角色权限后用户权限未变 | JWT 内含权限快照，让该用户重新登录 |
| 城市列表为空 | 生产接口网络异常，检查服务器出网（gw.chagee.com / gj-api.bwcj.com） |

## 13. 下单决策系统（2026-09-28）

> 依据 `docs/decision_api_contract.md`（契约）与 `docs/decision_system_design.md`（方案）。
> 目标：接单前量化核算「客户支付价 − 券采购成本 − 差额实付 − 杂费」的利润，自动推荐
> 用哪张券、在哪个账号下单；利润不达标的单直接拦截留痕。

**权限**：套餐配置 / 券成本与阈值 / 扫描 / 报表 / 决策流水 → `decision:manage`
（admin 与 operator 内置拥有，viewer 无）；工作台「决策评估」→ `feature:order`（与下单同权限）。

### 13.1 套餐配置（下单决策 → 套餐配置）

套餐 = 一类可接单的范围约定（客户支付价区间 + 可用时段 + 商品圈定 + 套餐级利润下限）：

1. **新增/编辑**：名称、客户支付价区间（最大填 0 = 不设上限）、可用时段（`HH:MM:SS`，
   支持跨零点如 22:00:00~06:00:00，留空 = 全天）、套餐级最低利润（留空 = 用全局配置）；
2. **商品子表格**：从菜单选品（自动回填商品名与面价），同一套餐每 sku 仅一行；需溢价券的
   商品勾选「溢价」，可为常规券/溢价券分别配置选券规则（模板包含/正则/券码前缀，不配 = 不限）；
   **不添加任何商品 = 全品类套餐**；
3. **列表操作**：开放开关（el-switch 即时生效，临时下架用）、关键字/开放状态搜索、编辑、删除；
4. 套餐仅约束 decide 与工作台评估，不影响既有 F5 下单流程。

（截图位：套餐配置页列表 + 编辑弹窗含商品子表格与券规则下拉）

### 13.2 券成本与阈值（下单决策 → 券成本与阈值）

**Tab1 成本规则**——把每类券映射为实际采购价：

1. 逐条新增：规则名、匹配方式四选一（模板全等 / 模板包含 / 权益正则 / 券码前缀）、
   面额校验（非空时须等于券面额，用于区分同模板不同面额）、**采购成本**、优先级
   （数字小的先匹配）、启用开关；
2. **批量导入**：粘贴 JSON 文本（元素字段同表单）→ 重复名称自动跳过、非法条目进错误
   列表不中断；
3. **扫描券库存**：全账号拉券（同优惠券全量查询语义）+ 成本盘点，返回扫描账号数、
   有成本/无成本券张数、总面额与总成本预估；「无成本」占比高 = 规则库缺该类券的采购价，
   回表单补录；
4. 券库存列表：每张券带分型（面额/折扣/兑换/未知）、成本与来源（规则命中 or 按面额×系数
   保守估算）、本地可用性判定（过期/门槛高于面额等）与归属账号。

**Tab2 决策配置**——全局阈值：最低利润（每单底线，元）、最低利润率（%，留空不启用）、
每单杂费（元）、成本兜底系数（规则未命中的券按 面额×该系数 保守计，默认 1.0）。

（截图位：券成本页 Tab1 规则表格 + 导入弹窗；Tab2 配置表单）

### 13.3 工作台决策评估（下单工作台，选完商品后）

步骤②选完商品后出现「决策评估」卡：

1. 输入**客户支付价**（客户实际付给我们的金额）→ 点「评估」；
2. 展示成本明细：茶姬总额（本地菜单价估算，标 `menu`；开「深度评估」后为服务端真实试算，
   标 `settle`）、预计抵扣（折扣/兑换类为估算值，成单后以服务端实扣对账）、券采购成本、
   差额实付、杂费、**利润与利润率**，以及判定阈值（套餐级或全局）；
3. **绿灯（pass）**：显示推荐账号与推荐券 + 备选票；点「应用推荐」自动切换账号、选中
   推荐券，提交下单时自动携带 `decision_log_id`（成单后回填实际抵扣/实付，进盈利报表）；
4. **红灯（blocked）**：显示拦截原因（见下表），提交按钮禁用提示。不加决策参数时旧下单
   流程照常可用（决策只做建议与拦截展示，不破坏 F5 既有能力）。

**常见 blocked 原因解读**：

| 提示 | 含义与处理 |
|---|---|
| 利润 X 元低于最低利润 Y 元 | 客户支付价太低或券成本太高：与客户改价，或到券成本页核对采购价是否录高 |
| 利润率 X% 低于最低利润率 Y% | 单笔金额大但利润率薄：确认是否值得接，或调低全局/套餐利润率阈值 |
| 最佳券候选未过阈值…不允许原价单 | 有券但都不赚钱，且未勾选「允许原价单」；确认后可勾选允许原价单再评估 |
| 无可用券候选（在线账号无未使用的有效券） | 囤券用尽或已过期：到券成本页扫描盘点库存，补充囤券 |
| 指定套餐 #N 未命中当前单 | 价格区间/时段/商品圈定与当前单不符：换套餐或调整套餐配置 |
| skuId 不在门店菜单中 | 客户链接对应的商品该门店无售：换门店或与客户确认商品 |

（截图位：工作台决策评估卡——pass 态成本明细 + 应用推荐按钮 / blocked 态原因提示）

### 13.4 盈利报表与仪表盘盈利卡

- **仪表盘盈利卡**（近 7 日）：成单数 / 累计利润 / 平均利润率 / 拦截（blocked）次数，
  与订单/券趋势卡同屏；
- **盈利报表**（`GET /api/ops/decision/profit-report`，报表导出与看板口径一致）：
  汇总（成单数/收入/成本/利润/平均利润率/拦截数）+ 按套餐聚合 + 按券模板聚合；
  **只统计真实成单的订单**（评估未成单的不计金额，防止报价刷高利润）；
- **决策流水**：每次评估（含 blocked）全量留痕，成单行回填服务端实际抵扣与实付，
  供估算偏差对账（折扣券的预计抵扣 vs 实际抵扣）。

### 券成本子类（券成本与阈值 → 成本子类 Tab）

子类是券资产的业务分类（采购付费/活动免费/银行渠道/其他），按券名等规则自动归类，**只做分类不影响成本价**（成本价仍由「成本规则」Tab 决定）。表格展示每个子类当前的券数/面额/成本合计（仅当前有效券）。

- 新增子类：填写名称/业务类型/匹配方式与匹配值（语义与成本规则一致）/优先级（小者优先，用于一券命中多个子类时定归属）
- 成本规则可挂「所属子类」便于组织；删除子类后挂靠规则自动回到未分类
- 「查看券」跳转优惠券查询档案库并自动按该子类筛选；档案库也可在筛选行按子类过滤（含"未分类"），每行显示成本价（未配置规则时标"待定"=按面额兜底估算）与子类标签
