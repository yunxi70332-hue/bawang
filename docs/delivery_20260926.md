## 五、当日定案的关键技术结论

1. **三场景判据（互斥且 createOrder 前已知）**：settlePrice 响应 `tradeFundInfo.buyerRealPrice` — "0"→零元（免支付腿，响应仅 `{orderNo}`，下一跳即 s3）；>0→差额（响应含 payUrl/payNo，支付宝 alipay.trade.app.pay、银联商务 chinaums 收单）
2. **待支付态**：orderStatus=1；`paymentExpiryTime`（下单+10 分钟）与 `paymentExpiryType:"autoCancel"` 仅此态出现；有效支付窗口 = min(茶姬 10min, 支付宝 30m) = **10 分钟**；超时 s7 终态不可救单
3. **续付机制**：`continuePay{tcode,userId,orderNo,channelCode:"UnionPay",payType:60}` 重铸全新支付串（新 out_trade_no + 重签），免走购物车
4. **券标识三处统一**：券列表 `couponCode` == 折扣行 `discountId` == 订单 `orderPromotions.promotionId`（核销锚点）
5. **下单可用券入口** = settlePrice 响应 `assetInfo.userCouponInfo.availableCouponList`（order-coupon-list 生产 404 未部署）
6. **状态枚举**：1=待支付 / 3=制作中 / 6=已完成(T0xxx) / 7=已取消；取餐码为门店级日序列（同店同日 TA0001→TA0002）
7. **轮询行为**：待支付期无后台心跳，页面/事件驱动（到期前 1s 有一次 detail；收银台期间零轮询）；支付完成后 getOrderDetail 一次带回状态+pickupNo；取餐页 getWaitingInfo 2-3s/拍
8. **链路工程根因**（设备换新）：CA 必须按 subject_hash_old（**MD5** 前 4 字节小端）命名（`c8750f0d.0`）；magisk 设备需 chcon `system_file` 或直写 /system（本机 / 为 ext4 可 remount）
